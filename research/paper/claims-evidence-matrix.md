## Reproducibility audit

The current artifact fails the paper's own reproduction bar:

- The dedicated `run-eval.sh` servers used `kaetram_eval` while the wrapper reset and harness snapshots targeted `kaetram_devlopment`. The conservative main-branch exposure window is April 25 through PR #37's July 22 merge; a fixed branch existed from July 18. Results from that dedicated lane are quarantined unless they attest the fixed branch or prove clean starts. The headline r10 and June OPD Core-3 values use the separate 9001/9011/9021 orchestrator path, so PR #37's specific mismatch does not directly implicate them. The July E4 (`run_20260711_153427`), E3-prime (`run_20260713_084905`), and Arm-C (`run_20260713_191230`) bundles also have the orchestrator-only `dataset/raw/agent_*/runs/run_*` layout; `run-eval.sh` writes instead to `dataset/eval/runs/*`. PR #37 therefore does not directly implicate those three headline values either. Their recovered first model-visible states are canonical, but the exact historical reset command and server revision remain unattested.
- `dashboard/db.py` keys quest-stage snapshots by internal quest ID, while the historical `eval_harness.py` path looked up display names. A deterministic fixture could score completed internal `foresting` as zero. Draft PR #53 corrects the mapping and covers all 3+3+4 stages; prospective Core-3 results remain blocked until that fix is merged and deployed.
- The r10 credit and comparison analyses rerun successfully when pointed at the recovered external paths, reproducing base `[7,7,7,7]`, SFT `[3,1,2]`, exact Mann–Whitney `p=0.0286`, and Foresting 8/12 versus 1/9. A clone without the mounted recovery cannot regenerate them.
- The r10 and full July raw logs are not checked into or released with the repository. The recovered run directories are content-bound by `research/audits/historical-run-digests.json` and `research/audits/july-mechanism-run-digests.json`; the latter deterministically regenerates the nine protocol-boundary scores in `research/audits/july-mechanism-results.json`. `research/artifacts/july-score-replay-v1/` is a reviewer-accessible, anonymous score projection with source-record/log bindings and an exact clean-clone replay command. It supports score verification but not independent repetition of the private raw-to-projection extraction.
- OPD gate summaries are checked in, but their input records and fixed external test set are absent.
- The round-two and round-three gates report `0/0` parameter-emitting completions, so the format check is vacuous.
- Several round-three “non-degenerate” samples are irrelevant prose, code, refusals, or fake tool syntax; the checker detects repetition, not task validity.
- Draft PR #46 adds an exact Python 3.12 lock and safe clean-clone bootstrap; a fresh temporary clone passed 143 CPU unit tests with 31 documented asset/service skips. This proves prospective local unit collection only, not training, live gameplay, checkpoints, historical results, or table regeneration.
- `eval_harness.py` reads `SCENARIOS[scenario]["max_turns"]` while current scenarios define `duration_minutes`, which can crash result saving.
- Base and SFT rendering differ: base passes native `tools=` schemas to the Qwen template; SFT intentionally omits them.
- Arena PR #47 carries deterministic per-replicate inference and environment seeds and verifies a game startup attestation. Kaetram-Open draft PR #333 centralizes server/common gameplay draws and rejects pre-seed draws, but it is not merged, deployed, or verified in a live run. Confirmatory launch therefore remains fail-closed.
- The factorial launcher now seals a portable, self-hashed prelaunch ledger, resolved prompts, exact pre-rewrite endpoint emissions, parsed tool-transition transcripts, state-boundary snapshots, launcher/results files, and an exact requested/completed-cell inventory that binds the prelaunch digest. Analysis must use the same clean registered commit and records source-file hashes. This prospective contract has not yet produced a live bundle.
- The future factorial now binds an outcome-blind executable analysis contract: seven exact paired-cluster formulas, paired Student-t inference, seven-way Bonferroni p-values and 99.2857% intervals, strict ±3-stage practical-relevance rules, paired d/g definitions, conservative zero-variance handling, a scipy 1.18.0 working-normal-model power calculation, and a no-replacement incomplete-run policy. This improves prospective validity but is not outcome evidence.
- The separate short-horizon local pilot did produce a complete retained bundle: 9/9 completed cells, hash-identified public weight blobs under one common Base tokenizer/patched renderer, paired inference/environment seeds, exact canonical-start projections, no logged `API error:` lines in retained stderr, and 261 rehashed files in sealed per-cell inventories. It records one prospective local execution only; it neither establishes independent reproducibility nor substitutes for the six-hour weights × recovery factorial.
- The preregistered 30-minute local factorial then completed all 18 Base/R2/R3 × recovery off/on cells. Its one-time export rehashed 1,266 files; anonymous exact CSVs and clarified tables are committed, while the complete report, receipt, and raw bundle remain local. The run is `legacy_v1_unattested`. Four cells advanced one stage; zero of 958 generations were malformed or recovery-eligible. The recovery manipulation therefore failed to engage, so this run does not identify a recovery effect and does not substitute for an independently powered confirmatory study.
- The V1 trigger-incidence follow-up is checked in as a complete identity-scrubbed raw bundle. All 1,200 request rows, the frozen design, endpoint attestations, analysis, and manifests verify from a clean checkout. The producer verifier, an independently implemented outcome auditor, and a post-outcome seed-diversity audit agree. The latter found that all five nominal seeds within every state-condition group produced the same normalized response payload; rates and state-level contrasts survive collapsing, but the effective output grid is 20 states per cell and supports no stochastic uncertainty. V2 separately repairs the sampling path on an outcome-unseen panel and is reviewer-recomputable from its checked-in raw artifact and local anonymous projection.
- The prospective state seeder restores persistent player state, not the complete shared world. Manuscript claims are therefore limited to player-state initialization unless NPC, mob, resource, concurrent-player, clock, and environment-RNG state are also sealed and restored.

The V2 routing tables are reproducible from their versioned review projection and standalone verifier. Historical score tables remain descriptive until a clean, documented environment can regenerate their source projections from released raw bundles.
